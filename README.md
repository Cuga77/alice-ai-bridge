# alice-ai-bridge

Мост между навыком **Яндекс Алисы** и любой LLM с OpenAI-совместимым API:
локальной (Ollama, LM Studio, vLLM) или облачной (OpenAI, OpenRouter и т. п.).

Сервис принимает вебхуки от Яндекс Диалогов, отправляет вопрос пользователя в
`/chat/completions` и возвращает Алисе ответ обычным текстом.

## Возможности

- Один файл, только стандартная библиотека Go, без зависимостей; Docker-образ ~16 МБ.
- Длинные ответы частями. Алиса ждёт навык около 3 с, поэтому мост через ~2.5 с
  отдаёт готовые законченные предложения и спрашивает «Продолжить?», а модель тем
  временем генерирует дальше. Следующая часть — по «дальше», «да», «ещё».
  Новый вопрос обрывает недосказанный ответ.
- История диалога в памяти (последние `HISTORY_TURNS` пар реплик, хранится 10 минут).
- Ограничение частоты запросов на пользователя (`RATE_PER_MIN`).
- Текст готовится для озвучки: без markdown, ссылок и эмодзи, пункты списков
  становятся предложениями, сокращения раскрываются («т.е.» → «то есть»).
- Модель знает текущие дату, время и день недели (часовой пояс — `TIMEZONE`
  или из запроса Алисы).
- Вопросы, которые Яндекс пометил как опасные (`dangerous_context`), не уходят
  в модель — навык отвечает фиксированной фразой (`DANGER_REPLY`).
- В модель уходит исходная фраза пользователя с регистром и знаками препинания.
- Запросы принимаются только от своего навыка (`ALLOWED_SKILL_ID`).
- Настройки из файла `.env`.
- Лог по каждому ответу: длина части, время ожидания, состояние генерации.
- Корректная остановка: по Ctrl+C или `SIGTERM` фоновые генерации отменяются.
- Служебные команды:
  - `хватит`, `выйти`, `стоп` — завершить сессию;
  - `забудь`, `начни сначала`, `новый диалог` — сбросить историю;
  - `дальше`, `продолжи`, `продолжай`, `ещё`, `да`, `давай` — следующая часть ответа;
  - `ping` — проверка, ответ `pong`.

## Как это устроено

```
Станция / приложение Яндекса
        │
Яндекс Диалоги ──HTTPS──▶ туннель (tuna, cloudflared, …) ──▶ мост :8080/alice ──▶ Ollama :11434
```

Яндекс обращается к навыку по публичному HTTPS-адресу. Если мост запущен на
домашнем компьютере, нужен туннель, который выдаст такой адрес.

## Запуск

Понадобятся Docker с Compose и аккаунт Яндекса. Go нужен только для запуска
без Docker (версия — см. `go.mod`).

### 1. Настройки

Все настройки хранятся в файле `.env` в папке проекта: его читают и
`docker compose`, и сам мост. Файл в git не попадает — ключи API храните только в нём.

```bash
cp .env.example .env
```

Что запускать, задаёт `COMPOSE_PROFILES`:

| `COMPOSE_PROFILES` | Что поднимается                     | Когда                                         |
|--------------------|-------------------------------------|-----------------------------------------------|
| `ollama`           | мост + Ollama с моделью             | локальная модель (по умолчанию в `.env.example`) |
| *(пусто)*          | только мост                         | облачная модель (Gemini, OpenAI…) и туннель   |
| `caddy`            | мост + Caddy с HTTPS                | VPS с доменом, облачная модель                |
| `ollama,caddy`     | мост + Ollama + Caddy               | VPS с доменом и локальной моделью             |

### 2. Запуск в Docker

```bash
docker compose up -d --build
docker compose logs -f               # логи; Ctrl+C — выйти из просмотра
```

Сервисы:
- `bridge` — мост, слушает `127.0.0.1:8080` (порт меняется через `BRIDGE_PORT`).
  Образ собирается из `Dockerfile`: статический бинарник на distroless, ~16 МБ.
- `ollama` — сервер моделей, модели хранятся в volume `ollama`.
  Модель не выгружается из памяти (`OLLAMA_KEEP_ALIVE=-1`): холодная загрузка
  не укладывается в таймаут Алисы. `OLLAMA_NUM_PARALLEL=2` — два диалога
  обрабатываются одновременно, а не по очереди.
- `ollama-pull` — одноразовый: скачивает модель из `LLM_MODEL`, прогревает её
  и завершается. Ход загрузки: `docker compose logs -f ollama-pull`.
- `caddy` — HTTPS-прокси для VPS, см. [Перенос на VPS](#перенос-на-vps).

Все сервисы перезапускаются сами — после падения и после перезагрузки сервера.
Внутри Docker мост обращается к Ollama по адресу `http://ollama:11434/v1`;
если `LLM_BASE_URL` задан в `.env`, используется он.

После изменения `.env` или кода: `docker compose up -d --build`.

Проверка:

```bash
curl -s localhost:8080/alice -d '{"request":{"command":"привет"},"session":{"session_id":"s1","skill_id":"<ID навыка>","user_id":"u1"}}'
```

### Запуск без Docker (для разработки)

```bash
docker compose up -d ollama ollama-pull   # только Ollama (или своя установка Ollama)
go run .
# listening on :8080/alice, llm: http://localhost:11434/v1 model=gemma3:1b
```

Без Docker мост сам читает `.env` из текущей папки; переменные окружения важнее
значений из файла. Не запускайте одновременно мост в Docker и `go run` — оба
займут порт 8080.

### 3. Публичный адрес

На VPS с доменом туннель не нужен — HTTPS даёт Caddy, см. [Перенос на VPS](#перенос-на-vps).
На домашнем компьютере запустите туннель к `localhost:8080`, например:

- **[tuna](https://tuna.am)** (нужна регистрация, хорошо работает из России):
  ```bash
  tuna http 8080
  ```
- **cloudflared** (без регистрации):
  ```bash
  docker run --rm --network host cloudflare/cloudflared:latest tunnel --protocol http2 --url http://localhost:8080
  ```
  `--protocol http2` нужен, если включён VPN: через него QUIC часто не проходит
  и туннель постоянно переподключается. Учтите, что серверы Яндекса не всегда
  могут достучаться до `*.trycloudflare.com`.

Туннель выдаст адрес вида `https://xxxx.ru.tuna.am`. Webhook навыка — этот адрес
плюс `/alice`. На бесплатных тарифах адрес обычно меняется при каждом перезапуске
туннеля, поэтому для постоянной работы зарезервируйте фиксированный поддомен.

### 4. Навык в Яндекс Диалогах

1. Откройте [dialogs.yandex.ru/developer](https://dialogs.yandex.ru/developer) →
   «Создать диалог» → «Навык».
2. Заполните настройки:
   - **Название** — по нему навык запускают. Слишком общие названия
     («Умный помощник») модерация может не пропустить.
   - **Webhook URL** — `https://<адрес-туннеля>/alice`.
   - **Тип доступа** — «Приватный», если навык нужен только вам.
   - **Примеры запросов** — каждая строка содержит фразу целиком, с названием:
     ```
     Запусти навык Мой гид
     Спроси у навыка Мой гид, что посмотреть в Петербурге
     ```
   - **Активационные имена** — необязательно; нужны, если Алиса плохо
     распознаёт название.
   - Иконка, описание, категория, email — обязательны для публикации.
3. Сохраните и проверьте на вкладке «Тестирование».
4. **Закройте мост для чужих навыков.** Без этого любой, кто узнает адрес туннеля,
   сможет пользоваться вашей моделью и ключом API. ID навыка — поле `skill_id`
   в запросе на вкладке «Тестирование» (он же есть в адресе страницы навыка).
   Впишите его в `.env` и перезапустите мост:
   ```
   ALLOWED_SKILL_ID=5739f431-...
   ```
   Запросы с другим `skill_id` получат `403`, в логе моста —
   `rejected request from skill …`.
5. Нажмите «Опубликовать». Приватные навыки проходят упрощённую проверку —
   обычно от нескольких минут до пары часов.

### 5. Запуск на Станции

> «Алиса, запусти навык Мой гид»

Приватный навык доступен только в аккаунте Яндекса, в котором он создан.
Станция должна быть привязана к этому же аккаунту — проверить можно в приложении
«Дом с Алисой». Если Станция привязана к аккаунту другого члена семьи, создайте
навык под его аккаунтом: мост менять не нужно. Либо предоставьте ему доступ в вкладке 'Доступ'.

Навык работает, пока запущены Ollama, мост и туннель.

## Выбор модели

Алиса ждёт ответа около 3 с, поэтому важна скорость модели, а не только качество.

Смена модели:

```bash
LLM_MODEL=qwen3:0.6b docker compose up -d   # скачать и прогреть
LLM_MODEL=qwen3:0.6b go run .               # запустить мост с ней
```

> **qwen3 сначала «рассуждает»**, и ответ не укладывается в лимит Алисы.
> Отключите рассуждения: `LLM_REASONING_EFFORT=none`.

Управление моделями:

```bash
docker compose exec ollama ollama list       # скачанные модели
docker compose exec ollama ollama ps         # загруженные в память
docker compose exec ollama ollama rm <model> # удалить (иначе так и будет занимать RAM)
```

### Облачная модель

Подойдёт любой провайдер с OpenAI-совместимым API. Ollama в этом случае не нужна.

```bash
LLM_BASE_URL=https://api.openai.com/v1 \
LLM_API_KEY=sk-... \
LLM_MODEL=gpt-4o-mini \
go run .
```

#### Gemini (бесплатный ключ)

1. Войдите в [Google AI Studio](https://aistudio.google.com/apikey) с Google-аккаунтом
   и нажмите «Create API key». Ключ выглядит как `AIza...`.
2. Посмотрите, какие модели доступны на бесплатном тарифе и с какими лимитами:
   [aistudio.google.com/rate-limit](https://aistudio.google.com/rate-limit).
   Лимиты считаются на проект, суточные сбрасываются в полночь по тихоокеанскому времени.
3. Пропишите в `.env` (шаблон есть в `.env.example`) и перезапустите мост:
   ```
   LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai
   LLM_API_KEY=AIza...
   LLM_MODEL=gemini-3.5-flash-lite
   LLM_REASONING_EFFORT=minimal
   LLM_MAX_TOKENS=1000
   ```

- **`gemini-3.5-flash-lite`** — самая быстрая из актуальных моделей. Если её нет
  на бесплатном тарифе, возьмите другую Flash-модель из списка в AI Studio.
- **`LLM_REASONING_EFFORT=minimal`** — у моделей Gemini 3 рассуждения полностью
  не отключаются (`none` работает только для 2.5), `minimal` сводит их к минимуму.
- **`LLM_MAX_TOKENS`** считает и токены рассуждений, поэтому лимит выше, чем для Ollama.
- **Доступность по регионам.** Gemini API работает не во всех странах
  ([список](https://ai.google.dev/gemini-api/docs/available-regions)), в частности
  не в России. Тогда и получать ключ, и запускать мост нужно через VPN: трафик моста
  к `generativelanguage.googleapis.com` должен идти через него.
- На бесплатном тарифе Google может использовать запросы для улучшения своих моделей.
- Каждый вопрос — один запрос к API; «дальше» лимит не расходует.

## Перенос на VPS

1. **Сервер.** Подойдёт самый простой VPS с Docker. С облачной моделью хватит
   1 ядра и 1 ГБ RAM; для Ollama с `gemma3:1b` — от 2 ядер и 2–4 ГБ RAM, но на
   слабом CPU ответы будут медленнее, чем дома.
   Если нужен Gemini, берите сервер в стране, где он доступен
   ([список](https://ai.google.dev/gemini-api/docs/available-regions)) — тогда
   VPN не понадобится.
2. **Домен.** Создайте A-запись, указывающую на IP сервера. Своего домена нет —
   подойдёт бесплатный поддомен, например от DuckDNS.
3. **Порты.** Откройте 80 и 443 в файрволе сервера/панели хостинга: через 80
   Let's Encrypt проверяет домен, через 443 приходят запросы Алисы.
4. **Код и настройки:**
   ```bash
   git clone https://github.com/Cuga77/alice-ai-bridge.git && cd alice-ai-bridge
   cp .env.example .env
   ```
   В `.env`:
   ```
   COMPOSE_PROFILES=caddy          # или ollama,caddy для локальной модели
   DOMAIN=alice.example.com
   ALLOWED_SKILL_ID=...
   TIMEZONE=Europe/Moscow
   # + настройки модели (например, блок Gemini)
   ```
5. **Запуск:**
   ```bash
   docker compose up -d --build
   docker compose logs -f caddy     # дождаться получения сертификата
   curl -s https://alice.example.com/alice -d '{"request":{"command":"ping"},"session":{"session_id":"s1","skill_id":"<ID навыка>"}}'
   ```
6. **Навык.** В Яндекс Диалогах поменяйте Webhook URL на
   `https://alice.example.com/alice` и снова опубликуйте навык (правка
   опубликованного навыка проходит модерацию). Туннель дома после этого
   можно остановить.

Обновление на сервере: `git pull && docker compose up -d --build`.

## Логи

Мост пишет по строке на каждую часть ответа и на каждую генерацию. Первые
8 символов — начало ID сессии, по ним видно, что относится к одному диалогу:

```
c121f282 answer: 174 chars in 2.501s (more)          # первая часть, ответ ещё генерируется
c121f282 llm done in 6.2s (515 chars)                # модель закончила
c121f282 continue: 340 chars in 2ms (last)           # «дальше» — последняя часть
623fd18f answer: 0 chars in 2.5s (still thinking)    # модель не успела ни одного предложения
623fd18f llm cancelled after 3.1s (120 chars)        # пользователь задал новый вопрос
9a1b2c3d dangerous_context: fixed reply
```

Состояния: `more` — будет продолжение, `last` — ответ закончен, `still thinking` —
за отведённое время готового текста нет (модель слишком медленная), `empty` — ошибка
или пустой ответ модели. Тексты вопросов и ответов в лог не пишутся.

## Если не работает

| Симптом | Что проверить |
|---|---|
| Мост отвечает «Не получилось ответить» | Запущена ли Ollama и скачана ли модель: `docker compose exec ollama ollama list` |
| На первый вопрос всегда «Ещё думаю», в логе `still thinking` | Модель слишком медленная — возьмите меньше; для qwen3 задайте `LLM_REASONING_EFFORT=none` |
| Модель ошибается со временем на несколько часов | Алиса часто присылает часовой пояс `UTC` — задайте свой: `TIMEZONE=Europe/Moscow` |
| В консоли Диалогов «empty response» | Запрос не дошёл до моста: проверьте Webhook URL (адрес туннеля мог смениться, в конце должно быть `/alice`) и что туннель запущен |
| Туннель постоянно переподключается | Мешает VPN: для cloudflared добавьте `--protocol http2` или исключите туннель из VPN |
| Gemini: `llm status 400 … location is not supported` | Регион не поддерживается — запускайте мост через VPN |
| Gemini: `llm status 429` | Исчерпан бесплатный лимит — подождите или смените модель |
| В консоли Диалогов ошибка, в логе моста `rejected request from skill` | `ALLOWED_SKILL_ID` не совпадает с ID навыка |
| Станция не находит навык | Навык опубликован? Станция привязана к тому же аккаунту, что и консоль Диалогов? |

## Настройки (переменные окружения)

Задаются в окружении или в файле `.env`; окружение важнее.

| Переменная             | По умолчанию                              | Описание                                         |
|------------------------|-------------------------------------------|--------------------------------------------------|
| `LLM_BASE_URL`         | `http://localhost:11434/v1`               | Базовый URL OpenAI-совместимого API              |
| `LLM_API_KEY`          | —                                         | Ключ API (заголовок `Authorization: Bearer`)     |
| `LLM_MODEL`            | `gemma3:1b`                               | Имя модели                                       |
| `LLM_SYSTEM`           | `Отвечай по-русски, кратко…`              | Системный промпт; текущие дата и время добавляются к нему автоматически |
| `LLM_REASONING_EFFORT` | —                                         | Передаётся как `reasoning_effort`; для qwen3 — `none` |
| `LLM_MAX_TOKENS`       | `300`                                     | Лимит токенов всего ответа                       |
| `LLM_TIMEOUT_MS`       | `2500`                                    | Сколько ждать модель перед ответом Алисе, мс     |
| `LLM_GEN_TIMEOUT_MS`   | `60000`                                   | Максимальное время генерации всего ответа, мс    |
| `CHUNK_RUNES`          | `600`                                     | Максимальная длина одной части ответа, символов  |
| `HISTORY_TURNS`        | `5`                                       | Сколько пар «вопрос–ответ» помнить               |
| `RATE_PER_MIN`         | `10`                                      | Запросов в минуту на пользователя                |
| `LISTEN_ADDR`          | `:8080`                                   | Адрес HTTP-сервера                               |
| `WEBHOOK_PATH`         | `/alice`                                  | Путь вебхука                                     |
| `ALLOWED_SKILL_ID`     | —                                         | ID навыка (через запятую — несколько); остальные запросы получают `403`. Если не задан, принимаются все |
| `COMPOSE_PROFILES`     | —                                         | Docker: какие сервисы запускать (`ollama`, `caddy`) |
| `DOMAIN`               | —                                         | Docker, профиль `caddy`: домен для HTTPS         |
| `BRIDGE_PORT`          | `8080`                                    | Docker: порт моста на `127.0.0.1`                |
| `ENV_FILE`             | `.env`                                    | Путь к файлу с настройками                       |
| `TIMEZONE`             | из запроса Алисы, иначе `UTC`             | Часовой пояс для даты и времени в промпте, например `Europe/Moscow` |
| `DANGER_REPLY`         | «Я не могу помочь с этим…»                | Ответ на вопросы с пометкой `dangerous_context`  |

## Остановка

```bash
docker compose down      # остановить всё, модели и сертификаты остаются в volume
docker compose down -v   # остановить и удалить скачанные модели и сертификаты
```
